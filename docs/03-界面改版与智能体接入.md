# 一、界面视觉改版

## 1.1 问题诊断：之前的"AI 味"从哪来

| 之前的做法 | 为什么看起来像"AI 做的" | 本次的替代方案 |
| --- | --- | --- |
| 紫蓝主色（#5B7CFA）+ 渐变翻卡 | 紫蓝渐变是 AI 生成界面的默认审美，同质化严重 | 换成**墨绿**主色 + **暖米白**纸底，纯色不用渐变 |
| 圆角 16–20dp + 柔和投影 | 大圆角 + 阴影堆叠 = 模板感 | 圆角收到 **10–12**，投影去掉，改用 **1px 发丝描边**分层 |
| 圆形图标气泡（68px 圆形 + 10% 底色） | 每个空状态都是同一个"彩色圆 + 图标"，很像生成式模板 | 改成小一号（54px）的**圆角方形**，描边 + 淡底，更克制 |
| 卡片铺满每一屏，层级靠阴影 | 视觉上"全是同样的白块"，没有主次 | 分区标题改成 **文字 + 右侧发丝线**，用留白和字重分层 |
| 满宽 `SegmentedButton` | Material 默认控件感强，和整体气质不搭 | 今日页换成**下划线式 tab**，设置页的分段按钮统一成细边框 + 淡底 |
| 强调色到处用（对勾、徽标、图标） | 高饱和点缀过多显得"花" | 强调色（陶土橙）只出现在**需要你注意**的地方 |
| 图标是靛蓝 + 橙色对勾 | 和界面新配色不统一 | 图标同步换成墨绿 + 陶土 |

## 1.4 预期效果

- 打开 App 的第一眼是**米白纸感**而不是亮蓝渐变，长时间看不刺眼；
- 卡片不再"浮"在页面上，而是像纸片一样"贴"着，层级靠线和留白而不是阴影；

# 二、智能体接入（LangGraph）

## 2.1 为什么是"一个独立服务"，而不是塞进 App

LangGraph 是 Python 生态的编排框架，Flutter/Dart 里没有对等实现。要在 App 里"用 LangGraph"，只能把它跑成一个服务，App 通过 HTTP 调用。

| 方案 | 可行性 | 取舍 |
| --- | --- | --- |
| **A. Python + LangGraph 服务（本次采用）** | ✅ 完全满足"用 LangGraph 建 Agent" | 多一个要启动的进程；但可以只在需要时启动 |
| B. Dart 端直接调 LLM + 提示词 | ✅ 最简单，纯客户端 | 不是 LangGraph；意图理解与工具调用都写死在提示词里，难扩展 |
| C. 端侧小模型（如 1B 级） | ❌ 手机上跑不动/太重 | 与"点开即用"冲突 |

因此关键设计是：**Agent 是可选增强，不是必经之路**。

- 没配置服务 → 走原来的「直连大模型」或「本地规则」，功能不受影响；
- 配置了但连不上 → 自动降级，并在确认页写明"智能体不可用，已改为…"；
- 只有配置且连通时，才用自然语言筛选。

## 2.2 数据流

```
App                                  Agent 服务（Python / LangGraph）
─────────────────────────────────    ──────────────────────────────────────
拍照 → ML Kit 本地 OCR
   │  ocr_text
   ├── 用户的「一句话要求」
   │      （如"只要名词" / "只提取我画圈的单词"）
   ▼
POST /extract  ───────────────────►  parse      规则切出候选词
                                     understand  LLM 理解意图（结构化）
                                     [vision]    可选：看图片找圈选（需授权）
                                     filter      按条件筛词（确定性代码）
                                     enrich      查音标 + 补释义
                                     review      筛空则回退并说明
   ◄───────────────────────────────  {words, notes, needs_image, ...}
   │
确认编辑页（可改/删/合并）→ 保存 SQLite
```

## 2.3 图的节点设计

| 节点 | 输入 | 输出 | 为什么这么拆 |
| --- | --- | --- | --- |
| `parse` | OCR 原文 | `candidates[]` | 复用 App 端规则，保证"有没有 Agent 结果都不跳变" |
| `understand` | 要求 + 候选词清单 | 结构化 `Intent` | 只让模型做它擅长的"理解"，不直接产出最终列表 |
| `vision` | 图片 + 候选词 | `keep_words[]` | 仅在用户开启图片上传且要求涉及圈选时进入 |
| `ask_image` | — | `needs_image=true` | 不偷偷上传图片，而是明确告诉用户"这需要授权" |
| `filter` | `Intent` + 候选 | `kept[]` | 筛选是**确定性代码**：模型给条件，代码执行，避免漏词 |
| `enrich` | `kept[]` | 带音标/释义 | 音标走词典接口（并发 8），释义缺失才让模型补 |
| `review` | `kept[]` | 最终结果 + 说明 | 筛空了自动回退为全部，避免"白拍一张" |

`Intent` 支持的条件：`keep_words`（白名单）、`keep_pos/drop_pos`（词性）、`require_meaning`、`require_phonetic`、`min/max_length`、`keyword_in_meaning`、`limit`、`mode`。

## 2.4 接口契约

```
POST /extract
{
  "ocr_text": "...", "instruction": "只要名词",
  "allow_vision": false, "image_base64": null, "max_words": 40
}
→
{
  "words": [{"word":"ability","phonetic":"/əˈbɪl.ə.ti/","meaning":"n. 能力","reason":""}],
  "raw_count": 5, "kept_count": 1,
  "intent": {"mode":"none","keep_pos":["n"],"rationale":"..."},
  "notes": ["共 5 个候选，保留 1 个"],
  "needs_image": false
}
```

`GET /health` 供 App「测试连接」使用。

## 2.5 App 端接入点

| 文件 | 改动 |
| --- | --- |
| `lib/services/agent_service.dart`（新增） | `AgentConfig` / `AgentResult` / `AgentService.extract()`；错误统一映射成已有的 `RecognitionFailure`；附 `instructionNeedsVision()` 与 `localInstructionFilter()` 两个纯函数 |
| `lib/services/recognize_controller.dart` | 提取阶段改为三级：**Agent → 直连大模型 → 本地规则**；新增 `setInstruction()`、`agentNotes`、`needsImage` |
| `lib/ui/pages/recognize_page.dart` | 新增「筛选要求」输入卡（含 5 个快捷标签）；未配置/需授权时的提示；把 `agentNotes` 传给确认页 |

| `lib/ui/pages/settings_page.dart` | 模型/智能体信息改为**只读**展示 + 说明弹窗；新增「允许上传照片识别圈选」开关 |

## 2.6 失败与降级策略

| 情况 | 表现 |
| --- | --- |
| 未配置服务地址 | 直接走直连大模型 / 本地规则；筛选卡下方提示"未连接智能体，只能本地粗筛" |
| 服务超时 / 502 | 自动降级为直连大模型，确认页顶部写明降级原因 |
| 服务返回空列表 | 抛 `noWords`，走失败页，可"改用本地规则识别" |
| 要求里提到"画圈"但没开图片上传 | 返回 `needs_image=true`，App 在筛选卡上提示"需要授权上传照片"；本次按全部单词处理 |
| 筛选后一个词都不剩 | Agent 的 `review` 节点自动回退为全部候选，并附说明 |
| 音标查不到 | 留空，不编造；确认页可手动补 |

## 2.7 隐私边界的变化（重要）

之前：**图片永不上传，只有 OCR 文字出网**。

现在多了一种例外，但**默认关闭**：

- 「允许上传照片识别圈选」开关默认 OFF，此时请求体里根本没有图片字段；
- 打开后，也只有当你这次的要求涉及"圈选/划线"时，才会把**这一张**照片随请求发给视觉模型；
- API Key 放在服务端 `.env`，App 端只有服务地址，反编译也拿不到 Key。

## 2.9 怎么用起来（3 步）

1. 电脑上：`cd agent && pip install -r requirements.txt`，复制 `.env.example` 为 `.env` 填 Key；
2. `python -m uvicorn app:app --host 0.0.0.0 --port 8787`（想先不花 Key 的钱可以加 `AGENT_MOCK=1`）；
3. 在 `config/app_config.json` 里把 `AGENT_BASE_URL` 填成 `http://电脑IP:8787`，并在 Run 配置加 `--dart-define-from-file=config/app_config.json`；也可以临时改 `lib/core/app_config.dart` 的 `_codeAgentBaseUrl` 兜底值。
   回到「拍照识别」，在「筛选要求」里写 `只保留名词`，再拍照即可。

# 三、配置方式调整：模型只写在代码里

## 3.1 改了什么

把"在 App 里填 Key"改成"在代码里配置"，App 内**不再有任何模型输入框**。

| 项 | 调整前 | 调整后 |
| --- | --- | --- |
| Base URL / API Key / 模型名 | App 内表单，存 SharedPreferences | `config/app_config.json`（gitignored）+ `--dart-define-from-file` 注入；`lib/core/app_config.dart` 只放非敏感兜底 |
| 智能体服务地址 | App 内表单 | 同上（`AGENT_BASE_URL` / `_codeAgentBaseUrl`） |
| 配置页 | `LlmSettingsPage` / `AgentSettingsPage` 两个表单页 | 两个页面**已删除**；「我的」里只留一行只读状态 + 说明弹窗 |
| 「允许上传照片识别圈选」 | 在智能体配置页里 | 保留为独立开关（隐私授权，不属于模型配置） |
| 「联网校验音标」「重复策略」等 | 保留 | 保留（这些是使用偏好，不是模型配置） |

## 3.2 为什么这样更合适

1. **Key 不再落到手机上**：以前存在 `SharedPreferences`（明文、可被备份导出），现在跟着构建走；
2. **换机/重装不用重填**：配置是编译产物的一部分，装上就是配好的；
3. **只有一个真相来源**：`AppConfig` 是唯一的读取点，`recognize_controller` 里所有 `_settings.baseUrl/apiKey/model` 全部替换成 `AppConfig.*`；
4. **仍然保留灵活性**：`String.fromEnvironment` 让 `--dart-define` / `--dart-define-from-file` 可以覆盖默认值，Key 不进源码也能用。

## 3.3 取舍（需要知道的代价）

- **改模型必须重新编译**：热重载无效，因为 `fromEnvironment` 在编译期就固化了；改完要重新 Run。
- **不适合给别人装**：Key 编进了 APK，反编译可见。要分发仍然要走代理（客户端只填代理地址）。
- 如果以后想让用户在 App 里填，恢复成本也很低：把 `AppConfig` 的常量改成 `SettingsStore` 的字段即可（本次删除的代码在 git 历史里）。
